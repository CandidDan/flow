Delegate the work, not the watching.

Flow turns coding agents into a delivery team you supervise at two points: the intent going in and the merge coming out. Everything in between is enforced by CI, and nothing reaches you until it’s actually done.

Get started What’s new in v2 Roadmap

AI can write code. You still can’t trust it to ship.

So you babysit it. You re-read every diff, re-run every check and re-feed context. The model was never the bottleneck. What’s missing is a system that makes “done” mean done, and without one, autonomy quietly collapses back into supervision.

Flow is that system. You approve the intent and the merge. CI holds the line in between.

How it works

A protocol that lives in your repo

There’s no service to log into and no database. Tasks are Markdown files on main, coordination is git, and enforcement is GitHub Actions.

  1. Approve the intent you

    State what you want and why, in your own words, in the repo. Approving it is your first touchpoint, and every task that follows points back to it.

  2. Scope it into tasks orchestrator

    Each task is a contract: acceptance criteria you can observe, the exact paths it may touch, and the goal it serves. A task is only ready when a fresh session could finish it without asking anything.

  3. A worker builds it agent

    A fresh session claims the task with a first-push-wins commit, builds on a branch, and a workflow opens the PR as a draft. Workers run in parallel, and scope lists keep them out of each other’s files.

  4. CI and independent reviewers judge it ci

    Build, lint, test, coverage and scope run as the gate. QA, code-review and security then review the PR as separate checks, outside the worker’s session, so nothing certifies its own work.

  5. You merge you

    Criteria ticked, each with the test that proves it. The merge stays human by design.

The gate

What’s enforced, not requested

Every row is a CI failure, not a convention. The gate doesn’t care who wrote the code: a human and an agent are held to the same bar.

CheckWhat it stops
touches-guardScope creep. A diff that strays outside the task’s declared paths fails. Needing more room is a reason to re-scope.
Independent reviewv2Self-certification. QA, code-review and security run on the PR, reading their config and helpers from the base branch, so a PR can’t narrow its own review.
Truncated-diff rulev2.2A review that didn’t read the whole change. If the diff is over the repo’s limit, all three review checks fail, whatever the reviewers said.
Store and plane guardsTask state being clobbered. Task files change only on main, and anything that reaches main without a PR is caught.
source_rootsv2Unchecked code. Every declared source tree gets its own check as a matrix job, and an undeclared tree fails the gate.
Coverage floorCoverage quietly falling. The floor is measured from your repo, never a round number.
CLAUDE.md ceilingv2Instruction bloat. It measures everything a session actually loads, imports included, against a per-repo limit.
flow-doctorStore drift: duplicate task ids, half-finished claims, a task in review with no PR, a goal that doesn’t exist.

What’s new in v2

Six releases in sixteen days

v2.0.0 through v2.2.0 shipped between 14 and 30 September 2026. 77 tasks have now gone through Flow’s own gate, because Flow is built with Flow.

Review moved out of the worker’s session

The worker no longer reviews its own output.

  • Three PR checks (qa, code-review, security), each with its model and trigger paths set in config
  • Base-branch planning, so a PR can’t switch off its own security review
  • Fails closed on a truncated diff, with a per-repo review.max_diff_bytes

Direction that survives the work

Every task traces back to something a human said they wanted.

  • VISION.md as the drift anchor, with goals and non-goals in the operator’s words
  • serves: on every task, checked against live goals
  • Intent store and template recording whose words an intent holds
  • flow-compass, a scheduled read-only drift audit

Runs while you’re away

Opt-in automation, off by default until you trust the loop.

  • Queue runner dispatches workers on a schedule and fails loudly when a run produces nothing verifiable
  • Triage turns issues into tasks, trusting only people who can already direct the repo
  • Recover and status keep task state in step with PRs, and retry lost races on main
  • Watchdog files an issue when scheduled automation stops running

Adoption and updates you don’t hand-edit

One protocol across many repos, and fixes that reach all of them.

  • flow-init makes adoption a command instead of a runbook to improvise
  • flow-sync delivers protocol and caller updates as a PR, and keeps your customised jobs
  • Public release repo with immutable tags and a v2 alias that moves only after a canary passes
  • Helpers ship with the workflow that calls them, so an alias move can’t break a repo that hasn’t synced

Bigger, messier repos

An admin app and a customer app in one repo, without special-casing.

  • source_roots matrix with dependency install and no duplicate runs
  • source_roots_ignore for folders that aren’t source
  • Per-repo limits for review size and context size

Agent-neutral

Flow is developed with Claude Code, but the protocol isn’t tied to it.

  • AGENTS.md points any coding agent at the same orchestrator skills
  • Third-party actions pinned to commit SHAs, so a moved tag can’t change what runs
  • Secrets passed by name, never inherited wholesale

Hardened in use

Every failure becomes a guardrail

Flow wasn’t designed on a whiteboard. Each of these happened in a real repo, and each is now a check.

A parse error in an unchecked folder silently dropped messages for about 7 days.
→ The gate refuses to merge any source tree it doesn’t parse.
A worker did all the work, then ended its turn without opening the PR.
→ PR creation moved off the model and onto a workflow.
On a 789 KB diff cut to 300 KB, QA refused to pass it while code-review and security passed it anyway.
→ A truncated diff now fails all three checks in code, not just in a prompt.
Moving the v2 alias turned every pinned repo red until it synced a new helper.
→ Workflows fetch their helpers from their own commit, so they ship as one unit.
The watchdog reported a nine-day outage that never happened, because it trusted the first result GitHub returned.
→ It now reads 100 runs and takes the newest success.

Get started

Adopt Flow in one session

The adoption runbooks are written for an agent to follow top to bottom. It stops where a human decision or a GitHub setting is needed. Use INIT.md for a new repo or RETROFIT.md for one with history.

Paste into a coding-agent session
Set this repo up on the Flow protocol. The runbook is project-template/INIT.md in github.com/CandidDan/flow-protocol. Clone that repo at tag v2.2.0 and read it first, then follow it exactly. Don't invent any value in .flow/config.yml: propose the commands from what's actually in this repo and ask me to confirm. Stop and give me the human-only list when you reach it.

What you’ll need

  1. A GitHub repo with Actions. Flow’s enforcement runs there.
  2. Five commands: install, build, lint, test and coverage. They’re the only per-stack part.
  3. Default workflow permissions set to “Read and write”. Without it the state workflows fail loudly.
  4. A fine-grained FLOW_PAT secret. Without it, auto-opened PRs don’t trigger the gate and can merge unchecked. This is the one to get right.

A good fit if

You’re solo or a small team running several projects on GitHub, handing real implementation work to coding agents, and you’d rather put effort into a gate that can’t be skipped than review everything by hand.

Know before you start

Flow has been built and validated by one operator across a handful of projects. Parallel workers are designed for, but no multi-person team has used it yet. It assumes small tasks with mostly separate file scopes. If you want a hosted tool with a UI, or you’re not on GitHub Actions, it isn’t for you yet.

Flow is a git-native protocol for trustworthy, parallel, agent-driven delivery. Your work stays in your repo.
