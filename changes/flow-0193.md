- **Flow 5.0.0: qa, code-review and security run in one review job that posts three check runs,
  and the auto-fix round reads those check runs** (`.github/workflows/_flow-review.yml`,
  `.github/workflows/_flow-kickback.yml`, `.flow/bin/flow-review.mjs`,
  `.flow/bin/flow-kickback.mjs`, flow-0193). **Caller action — MAJOR, three steps, in this
  order** (`docs/repinning-a-consuming-repo.md`, "Moving from `@v4` to `@v5`"): (1) repin the
  flow-sync caller to `@v5` and run flow-sync; its PR adds `checks: write` to `flow-review.yml`
  and replaces `actions: read` with `checks: read` in `flow-kickback.yml`; (2) merge that sync PR;
  (3) in branch protection, replace the required checks `flow-review / qa`,
  `flow-review / code-review` and `flow-review / security` with `qa`, `code-review` and
  `security`. **Canonical's own branch protection needs the same required-check change** once
  this merges.

  One `review` job, on one runner, replaces the three review jobs. Each review keeps its own model
  step, prompt, model and turn limit; no two share a model session. Before each model step the
  job deletes that review's `$RUNNER_TEMP/flow-review/<check>.json`; straight after it, a non-model
  step validates the file with the new `flow-review.mjs check-run` command (exported as
  `checkRunPayload`) and creates that review's check run on the PR head, before the next model
  step starts. A missing or invalid verdict file concludes `failure`, as does a truncated diff. A
  security review the plan skips makes no model call, and its check run concludes `skipped` with
  the reason in its summary. The `review` job fails when any of the three check runs is
  `failure`. `guide` and `intent-review` are unchanged and still advisory; neither creates a
  check run, and only the `review` job holds `checks: write`.

  `flow-kickback` now decides the round from the head commit's check runs named `qa`,
  `code-review` and `security` (new `flow-kickback.mjs failed-checks`, exported as
  `failedReviewChecks`), never from job names. A failed `security` still escalates and is never
  auto-fixed; the `review` job's own failure is not a signal.

  The plan summary now renders the security skip reason inside a code span, because it can carry
  names a PR author chose. Every template caller pins `@v5`, and `_flow-sync.yml`'s fallback ref
  is `v5`.
