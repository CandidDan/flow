- **A repo chooses where its worker runs, and new adopters get no automatic worker**
  (`.github/workflows/_flow-queue-runner.yml`, `project-template/.flow/bin/worker-host.mjs`,
  `project-template/.flow/config.yml`, flow-0170). **No caller action** for existing repos: a
  config with no `worker` key behaves as `github-actions`, exactly as before. To stop queue-runner
  starting a worker, add `worker: { host: manual }` (or `claude-routine`) to `.flow/config.yml`
  after flow-sync delivers `.flow/bin/worker-host.mjs`.

  queue-runner was about $60 of October's Actions bill across private repos, billed per minute
  while the runner waits on Claude, and every adopter got it whether or not they wanted Claude on
  Actions. `worker.host` is `manual | claude-routine | github-actions`; the template now ships
  `manual`. The `dispatch` job decides before the pick step, on scheduled and dispatched runs
  alike, and anything but `github-actions` ends the run green with the reason in the step
  summary. An unknown value fails the run naming the three allowed values.
