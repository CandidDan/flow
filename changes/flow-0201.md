- **Issue triage now acts on `approved`, `auto-ok` and `flow:trusted` only when the issue's
  history shows a permitted actor applied them** (`.github/workflows/_flow-triage.yml`,
  `project-template/.flow/bin/intake-trust.mjs`, flow-0201). A new `lanes` step reads each
  admitted issue's events before the agent runs. `approved` and `auto-ok` count only when their
  most recent application (after the label was last removed) was by a person, never a bot, who
  holds write, maintain or admin on the repo at the time triage runs. `flow:trusted` counts only
  when that application was by a login in `intake.trusted_labelers`; an empty list trusts nobody.
  The agent is told to use these verified lanes, not the raw labels, and every label that is
  present but not honoured prints one `flow-triage: label-not-honoured issue=… label=… actor=…
  reason=…` line. **Behaviour change. Caller action:** in a repo where a bot or app applied
  `approved` or `auto-ok`, or where the person who applied it has since lost write access,
  triage stops honouring that label — a person with write access removes and re-applies it.
