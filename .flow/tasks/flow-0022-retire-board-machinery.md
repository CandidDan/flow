## Context

ADR-0002 Amendment 1 chose a **computed** cross-project page over a **regenerated** artifact, and
flow-0019 builds it. Everything this task deletes is the regenerated generation:

- `.flow/board.html` — regenerated by the `board-builder` skill from the task files. Stale one
  second after it is written, by construction, and it round-trips human edits back into the store
  via `apply-board-edits.mjs` — a writable view, which is the shape `VISION.md` NG2 exists to
  forbid.
- `flightdeck/bin/flightdeck-state.mjs` — the offline aggregator. ADR-0002 demoted it to "the
  offline view rather than the primary one"; with mission control reading GitHub directly, the
  offline read has no remaining consumer.
- `flightdeck/projects.example.yml` — the registry. Enrolment is the `flow` GitHub topic now
  (decided 2026-08-19, per the topic-discovery model in
  `docs/handoff-vision-layer-review.md` §10.8), so a hand-maintained list is a second enrolment
  record that can silently disagree with the first.
- `flightdeck/.claude/agents/portfolio-manager.md` — reads local clones. That is the untrusted
  aggregation ADR-0002 was written about: a mounted clone lags `origin`, so its numbers look fresh
  and are not. **This one is rewritten, not deleted** — see the boundary below.

Leaving them shipped is a **G4** failure specifically: an adopting repo receives, and is told to
run, infra that canonical itself no longer runs or believes in. That is the "enrolled repo running
infra canonical can't name" case, arriving by publication rather than by drift.

Why G4 and not G5: G5 asks whether the question *"where is everything up to?"* is answered in one
computed place. flow-0019 answers it; deleting the superseded views adds no answering power to it.
What deleting them changes is what the fleet receives. That is G4's sentence, not G5's.

## Scope

**Does — delete:**

- `project-template/.flow/board.html`
- `project-template/.claude/skills/board-builder/SKILL.md` (and its now-empty directory)
- `flightdeck/bin/flightdeck-state.mjs` and `flightdeck/bin/flightdeck-state.test.mjs`
- `flightdeck/projects.example.yml`

**Does — edit:**

- `project-template/.flow/bin/flow-doctor.mjs`: remove the board-snapshot drift check (the
  `board.html` `const TASKS = […]` read and its three warnings) and the header lines that advertise
  it. **Keep the `STATUSES` import from `apply-board-edits.mjs`** — it is unrelated to the board
  and removing it breaks status validation.
- `project-template/.flow/bin/flow-doctor.test.mjs`: drop the drift test. Nothing replaces it — the
  check has no successor, because the artefact it validated is gone.
- `.gitattributes` and `project-template/.gitattributes`: remove the `.flow/board.html
  linguist-generated=true` line **only**. The `.flow/board-edits.json` line **stays** — see the
  boundary below.
- `.flow/bin/protocol-docs.test.mjs`: update the `.gitattributes` assertion to match (it currently
  asserts both lines exist), and the "absent on purpose" list that names `.flow/board.html`.
- `.gitignore` (root): remove the `flightdeck/projects.yml` private-registry entry.
- `project-template/.claude/settings.json`: drop `board-builder` from the `$comment`'s list of what
  the plugin makes work.
- `flightdeck/README.md` and `flightdeck/CLAUDE.md`: remove the registry and state-aggregation
  sections and point at mission control instead. Both are majority-registry today, so expect a
  rewrite rather than a trim.
- `flightdeck/.claude/agents/portfolio-manager.md`: **rewrite** so it reads GitHub directly —
  owner-scoped `topic:flow` discovery and the GitHub API/connector, the same enrolment and the same
  read-only posture mission control uses — instead of registry entries and local clone paths. Its
  digest logic, its blocked-tier classifier and its hard rules are still wanted and carry over
  unchanged; what changes is where the data comes from. Drop the step-4 instruction to write
  `flightdeck.html` — that is the regenerated artifact this task retires.
- `CHANGELOG.md`: one `## Unreleased` entry recording the removal, the bump class and the caller
  action (below).

**Deliberately does NOT:**

- **Remove `.flow/bin/apply-board-edits.mjs` or `project-template/.flow/bin/apply-board-edits.mjs`.**
  Despite the name it is the task-state writer for `_flow-status`, `_flow-done` and `_flow-recover`.
  Deleting it breaks status sync, done-marking and recovery in every consuming repo. Its
  `.flow/board-edits.json` transport, the `.gitattributes` line for that file, the
  `project-template/.gitignore` entry for it and `_flow-done.yml`'s use of it all stay exactly as
  they are. Renaming it to match what it actually does is a separate task nobody has written.
- **Touch `docs/adr/0001-*` or `docs/adr/0002-*`.** ADRs are dated records of decisions taken. A
  record that mentions the board is correct history; editing it to hide the board is falsifying the
  record. The retirement is recorded by a *new* ADR or an amendment, not by rewriting old ones —
  and that is not this task either.
- **Edit `project-template/.flow/bin/pick-task.test.mjs` or `touches-guard.test.mjs`.** Both use
  `.flow/board.html` as an arbitrary path *string* in glob-overlap assertions. They do not depend on
  the board existing, and churning them buys nothing.
- **Edit any file in `.flow/tasks/`.** Historical task files mention the board; that is history, and
  a PR touching the store fails the gate anyway.
- **Touch the prose runbooks and reference docs.** `INIT.md`, `RETROFIT.md`,
  `project-template/README.md`, `PROTOCOL.md`, `FLOW-handoff.html`, `docs/flow-map.html`,
  `docs/flow-infra-propagation-plan.md` and the root `CLAUDE.md` are **flow-0023**.
- **Bump `VERSION` or move a tag.** The release procedure in `docs/flow-versioning-policy.md` owns
  that; this task adds the `## Unreleased` entry it will be released from.

## The version bump: MINOR

Say it in the CHANGELOG entry, and it is **MINOR**, not MAJOR. The policy's tell for MAJOR is
explicit: *"if a change requires editing the per-repo callers, it is MAJOR."* This change edits no
caller — no thin `flow-*.yml` gains or loses a `permissions` grant, an input or a secret, and
`_flow-done` / `_flow-status` keep calling an unchanged `apply-board-edits.mjs`. The doctor change
is reusable-internal and rides the `v1` alias for free. The removed board check was WARNING-only,
so a synced repo that still has a `board.html` simply stops being told it has drifted; nothing goes
red. `.claude/skills/**` does not sync at all (`docs/handoff-vision-layer-review.md` §10.6), so an
adopted repo keeps its `board-builder` and its board working until it chooses otherwise.

**Caller action to record: optional.** An adopting repo may delete its own `.flow/board.html`, that
file's `.gitattributes` line and its copy of the `board-builder` skill. Nothing breaks if it does
not — the board simply stops being regenerated once the skill is gone.

## Notes / open questions

- **The portfolio-manager rewrite is mandatory, not optional.** Deleting `flightdeck-state.mjs`
  while leaving the agent reading local clones regresses it to precisely the untrusted-aggregation
  problem ADR-0002 was written about — worse than today, because today the agent is at least told
  to prefer the tested resolver. If the rewrite cannot be completed, block the task; do not ship
  the deletions without it.
- **Coverage will move, possibly downward.** `flightdeck-state.mjs` is 223 lines with 369 lines of
  tests — well above average coverage. Removing it takes covered lines out of the numerator as well
  as the denominator, so the percentage can fall even though nothing got worse. If it lands under
  83.5, the fix is more tests on what remains. **Never lower the floor to go green**, and never
  "fix" it by keeping dead code.
- **`flightdeck/` must not become an empty source root.** `.flow/config.yml` declares the whole
  tree, and a declared root that does not exist is a doctor PROBLEM while an empty lint target is a
  gate failure by design. flow-0019 lands `flightdeck/bin/liveness.mjs` and
  `flightdeck/bin/mission-control.mjs` first, which is one more reason this task is blocked behind
  it. Confirm those files are present before deleting the aggregator.
- **Order of collisions at unblock time.** `flow-doctor.mjs` + its test are flow-0017's;
  `flightdeck/README.md` is flow-0019's. flow-0019 will have merged by definition. Re-run
  `node .flow/bin/flow-doctor.mjs` when flipping this to `ready` and resolve any overlap warning it
  reports rather than assuming this list is still accurate.
